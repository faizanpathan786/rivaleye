# Signal-Centric Pipeline — Phase 4 (Persist Role Sections + API) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Persist the six role sections Phase 3 already generates into a new `report_role_sections` table, and expose them via a single API endpoint. The legacy report and all existing tables/endpoints are untouched.

**Architecture:** One additive migration (`report_role_sections` table, `section_type` enum, unique on `(report_id, section_type)`). The worker's `persistReport()` upserts one row per `section_type` alongside the existing legacy-table writes. One new API endpoint `GET /v1/reports/:id/sections` returns all six sections as `{ overview, founder, product, marketing, growth, evidence }`. Permission-guarded with `REPORTS_VIEW` per the api CLAUDE.md hard rule.

**Source spec:** `15-signal-centric-pipeline-redesign.md` §8 (Option A — `report_role_sections`) and §9 Phase 4.

**Scope guard:** Do NOT modify Stage A/B/C/D/E prompts or runners, the existing report tables/endpoints, or the web app. Phase 5 is the frontend.

## Task E1 — `report_role_sections` schema + generated migration

**Files:** Create `packages/api/src/db/schema/report-role-sections.ts`. Modify `packages/api/src/db/schema/index.ts`. Run `pnpm db:generate` from repo root.

- [ ] **Step 1:** create `packages/api/src/db/schema/report-role-sections.ts`:

```typescript
import { integer, jsonb, pgEnum, pgTable, timestamp, unique, uuid } from "drizzle-orm/pg-core";
import { reports } from "./reports";

export const report_section_type_enum = pgEnum("report_section_type", [
  "overview", "founder", "product", "marketing", "growth", "evidence",
]);
export type ReportSectionType = typeof report_section_type_enum.enumValues[number];

export const report_role_sections = pgTable(
  "report_role_sections",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    report_id: uuid("report_id")
      .notNull()
      .references(() => reports.id, { onDelete: "cascade" }),
    section_type: report_section_type_enum("section_type").notNull(),
    data: jsonb("data").$type<Record<string, unknown>>().notNull(),
    schema_version: integer("schema_version").notNull().default(1),
    created_at: timestamp("created_at").notNull().defaultNow(),
    updated_at: timestamp("updated_at").notNull().defaultNow(),
  },
  (t) => [
    unique("report_role_sections_report_section_uniq").on(t.report_id, t.section_type),
  ],
);

export type ReportRoleSection = typeof report_role_sections.$inferSelect;
export type NewReportRoleSection = typeof report_role_sections.$inferInsert;
```

- [ ] **Step 2:** in `packages/api/src/db/schema/index.ts`, add `export * from "./report-role-sections";`. Re-export the enum types in the existing typed-export block.

- [ ] **Step 3:** from repo root, `pnpm db:generate`. Confirm a new file appears in `packages/api/drizzle/`.

## Task E4 — API service + handler

**Files:** Modify `packages/api/src/services/reports.service.ts`, `packages/api/src/controllers/reports/index.ts`. Create `packages/api/src/controllers/reports/handlers/getSections.ts`.

- [ ] **Step 1:** in `reports.service.ts`, add `getReportSections(reportId: string)` that selects all `report_role_sections` rows for the report and returns them assembled as `{ overview, founder, product, marketing, growth, evidence }` (each is the row's `data` JSONB, or `null` if no row for that section_type). Return shape: `{ overview: unknown | null, founder: unknown | null, ..., evidence: unknown | null }`. (Don't validate against the Phase-3 dashboard Zod here — that's a frontend concern; just return the stored JSON.)

- [ ] **Step 2:** create `packages/api/src/controllers/reports/handlers/getSections.ts`:

```typescript
import { Elysia, t } from "elysia";
import { authPlugin } from "@/plugins/auth";
import { PERMISSIONS } from "@/types/permissions";
import { getReportSections } from "@/services/reports.service";

export const getSections = new Elysia()
  .use(authPlugin)
  .get(
    "/:id/sections",
    async ({ params }) => {
      const data = await getReportSections(params.id);
      return { data };
    },
    {
      params: t.Object({ id: t.String({ format: "uuid" }) }),
      auth: { permissions: [PERMISSIONS.REPORTS_VIEW] },
    },
  );
```

Adapt the exact `authPlugin` import path / `PERMISSIONS` member to match the codebase — read `packages/api/src/types/permissions.ts` and an existing handler (e.g. `getReport.ts`) to mirror its structure.

- [ ] **Step 3:** in `packages/api/src/controllers/reports/index.ts`, `.use(getSections)` on the reports sub-app. Mirror existing handlers' mounting.

- [ ] **Step 4:** `pnpm --filter @rivaleye/api type-check` — clean.
