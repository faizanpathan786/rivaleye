================================================================================
                             The Error Message
================================================================================

Currently, when you create a report without INNGEST_EVENT_KEY:

  HTTP Response:
    {
      "status": 400,
      "message": "Failed to create report",
      "error": "Inngest API Error: 401 Event key not found"
    }

This error means:
  - inngest.send() tried to authenticate
  - Inngest API couldn't find the event key
  - Request was rejected with 401 Unauthorized
  - Error bubbled up to API handler
  - API returned 400 to user

================================================================================
                        Why This Happened
================================================================================

The system was built to use Inngest for queueing jobs to workers.

Inngest requires:
  1. INNGEST_EVENT_KEY in environment
  2. Inngest server running (localhost:8288 for dev)

Without these, `inngest.send()` fails immediately.

The rest of the system (database, API logic, workers) is all correct.
It just needs this one piece to work.

================================================================================
                            Troubleshooting
================================================================================

Problem: Still getting 401 error
  → Check .env file has INNGEST_EVENT_KEY set
  → Check key format: should start with "sk-"
  → Run: echo $INNGEST_EVENT_KEY (should print key, not empty)

Problem: Test shows "INNGEST_EVENT_KEY is set: NO"
  → Key is in .env but environment variable not loaded
  → Restart terminal (source .env automatically in some shells)
  → Or explicitly: export $(cat .env | xargs)

Problem: Can't connect to localhost:8288
  → Run: npx inngest-cli@latest dev
  → Check no other process using port 8288

Problem: Workers connected but jobs still stuck
  → Check worker logs for errors
  → Verify worker handlers exist: packages/worker/src/scrape/fetch.ts
  → Check database schema matches workers' expectations
